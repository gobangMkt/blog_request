# 신청앱 폼 디자인 규율 (design-system)

> 대상: `15만원-여름특가/` · `10만원-CRM판매/` · `addon-direct-pay/` 등 **원장님이 폰으로 작성하는 신청 폼**. UI는 이 규율로 만든다.
> 대상 2: **운영 도구(마케팅팀 데스크톱, 예: `addon-direct-pay/paste.html`)**. 색·글자·입력·CTA는 폼과 같고, 폭(§6)과 운영 전용 부품(§4 하단)만 다르다.
> 등록: 2026-11-09 (디자인팀장). 2026.11.11 운영 도구 부품 추가. 정본 = 이미 출시된 15만원·10만원 폼의 실제 토큰. 새 부품·새 색을 만들면 화면에 그리기 전에 이 문서에 먼저 올린다.

## 0. 출발선과 다른 점 (사유 등록)
- 디자인팀장 출발선(`baseline/README.md`)의 키컬러는 민트(#25B9B9)지만, 이 앱은 **이미 출시된 폼 형제와 한 화면 문법**을 쓴다: 1차 액션·선택 = 파랑(`--pri #3182F6`), 구조 표식 = 청록(`--teal #00A0B0`). 같은 원장님이 같은 회사 폼을 연달아 쓰므로 형제와 같은 것이 먼저다(출발선의 "같은 회사 출시작이 표보다 먼저" 원칙).
- 출발선과 같게 가는 것: 면분리(회색 바닥 + 흰 카드), 읽히는 글 13px 이상, 12px 미만 금지, UI 이모지 금지, 제출 CTA 52px.
- **헤더는 폼마다 다를 수 있다(2026-11-09 토미 지시: "기존과 다르게, 히어로 헤더에 배경색").** 기존 15·10만원 폼은 흰 헤더(+연한 청록 그라데이션 히어로)다. 직접결제 폼은 **채색 히어로 헤더**(아래 §4)로 구분한다. 본문 카드·입력·버튼·글자 단계는 형제와 같게 두어, 헤더만 달라도 같은 회사 폼으로 읽히게 한다.

## 1. 색 — 역할로만 쓴다
| 역할 | 토큰 | 값 | 쓰는 곳 |
|---|---|---|---|
| 1차 액션·선택·링크 | `--pri` / `--pri-h` | #3182F6 / #1B6CF2 | 제출 버튼, 선택된 카드 테두리, 체크 토글, 텍스트 링크 |
| 구조 표식 | `--teal` / `--teal-bg` / `--teal-ink` | #00A0B0 / 7% / #00707C | 섹션 번호 원, 헤더 태그(연한 면 + `--teal-ink` 글자). 버튼·링크에 쓰지 않는다 |
| 히어로 면 | `--hero` / `--hero-tint` / `--hero-sub` | #007A87 / 흰 16% / 흰 90% | 채색 히어로 헤더의 바탕 / 그 위 태그 면 / 그 위 보조 글자. 흰 글자 대비 5.1:1(본문 크기 글자 가능). 이 면 위에 `--teal`(#00A0B0)은 쓰지 않는다(대비 3.2:1 미달) |
| 검증 통과 | `--ok` / `--ok-bg` / `--ok-ink` | #00C73C / #E8FBF0 / #00812A | "사용할 수 있어요" 피드백, 키워드 번호 원 |
| 오류 | `--err` / `--err-str` | #F04452 / #D92B2B | 입력 오류 테두리, 오류 문구 |
| 글자 | `--g900` 본문 / `--g700`·`--g600` 보조 / `--g500` 메타 / `--g400` 플레이스홀더 | #191F28 / #4A5568·#4E5968 / #8B95A1 / #B0B8C1 | 본문은 g900, 부연은 g600, 메타는 g500 |
| 면 | `--bg` 바닥 / `--sur` 카드 / `--info` 안내 / `--bdr` 선 / `--bdr-i` 안내 선 | #F2F4F6 / #FFF / #F8FAFF / #E5E8EB / #D0E2FF | |
| 팝업 바탕 | `--dim` | rgba(25,31,40,0.45) | 확인 팝업 `.modal` 뒤 화면을 덮는 면. 다른 곳에 쓰지 않는다 |
- 하드코딩 hex는 `:root` 토큰 선언 한 곳에만 둔다.
- **카테고리별 고유색 금지.** 구분은 색이 아니라 형태·위치가 한다.
- **초록(ok)은 "폼이 직접 확인한 사실"에만 쓴다.** 결제 완료처럼 폼이 모르는 사실을 초록 배지로 단정하지 않는다(2026-11-09 공개 폼 헤더 배지 사고).

## 2. 글자 — Pretendard, 단계 고정
| 단계 | 크기/굵기 | 용도 |
|---|---|---|
| 페이지 제목 | 24 / 800 | 헤더 h1, 한 화면에 1개 |
| 섹션 제목 | 18 / 800 | `.sec-title`, 모달 제목 20 / 800 |
| 필드 라벨 | 15 / 700 | `.field-label` |
| 입력 글자 | 16 / 400 | 입력·텍스트에어리어(iOS 확대 방지로 16 미만 금지) |
| 본문·안내 | 14~15 | 안내 문장, 카드 설명 |
| 보조·피드백 | 13 | 검증 문구, 글자 수, 링크. **12px 이하 금지** |
- 굵기 800은 **페이지 제목과 섹션 제목 두 곳만.** 단계 숫자·소제목 등 세 번째 자리에 800을 늘리지 않는다.
- 줄간격은 항상 명시: 제목 1.35, 본문 1.6. 한글은 `word-break: keep-all`.

## 3. 간격 — 4·8 스케일, 그릇이 소유한다
- 허용: 4 · 8 · 12 · 16 · 18 · 20 · 22. 카드 사이 12, 카드 안 패딩 22/18/20, 필드 사이 18, 라벨~입력 8.
- 입력 높이 50, 제출 버튼 52. 자식에 margin을 주지 말고 그릇의 `gap`/형제 간격으로 낸다.

## 5. 상태 표현 — 보이지 않는 상태는 없다
| 상태 | 표현 |
|---|---|
| 확인 중 | 회색 `fb.checking` 문구("확인 중이에요") |
| 통과 | ok 선 + 초록 글자 문구 |
| 오류 | err 선 + 빨간 글자 문구 + 힌트 한 줄 |
| 제출 중 | 버튼 라벨 교체 + 비활성 |
| **제출 불가(비활성)** | **회색 버튼이되 라벨이 남은 항목 하나를 말한다**("키워드를 1개 이상 입력해 주세요"). 이유 없는 회색 버튼 금지 |
| 완료 | 전용 화면(파란 체크 + 다음 일정 한 줄 이상) |
| 접근 불가 | 폼을 숨기고 이유를 쓴 전용 화면 |

## 6. 폰 폭
- 기준 391px, 컬럼 `max-width: 480px` 가운데 정렬, 가로 스크롤 금지(`scrollWidth ≤ innerWidth`).
- 2열은 이름·전화 같이 짧은 쌍과 선택 카드 둘에만. 그 외는 1열.
- 하단 고정 바가 있는 화면은 본문 하단 패딩 96px 이상.
- **운영 도구는 다르다**: `.wrap` 960 max + 좌우 16, 표 셀은 한 줄 유지, 640px 이하에서만 줄바꿈·열 숨김(토미 11.11 "폭을 넓히면 되지 굳이 모바일로").

## 7. 문구 (이 앱 폼 공통)
- 사용자 화면에 사람 말만. 해요체, 안내는 사실만. 결과가 폼 밖에서 정해지는 것(결제 확인 등)을 폼이 단정하지 않는다.
- 이모지 금지. 아이콘은 단색 SVG.
- 운영 도구는 설명 문장을 화면에 깔지 않고 툴팁(`.tip`)에 둔다(토미 11.11).
- 되돌릴 수 없는 외부 쓰기(시트 등록·알림톡)는 확인 팝업, 되돌릴 수 있는 체크는 팝업 없음(토미 11.11).
- 상태 목록은 단계 그룹이 아니라 시간순 한 표 + 풀어 쓴 상태 문구(토미 11.11).

## 8. 완료 전 확인 (tsc·빌드는 완료가 아니다)
391px 렌더 → ①가로 넘침 ②12px 이하 글자 0 ③링크 터치 영역 ④비활성 버튼 라벨 ⑤번호·순서 표식이 한 종류인지 → 형제 폼(15·10만원)과 나란히 대조 → 게시.

## 9. 알려진 부채 (2026-11-09 검토에서 🟡로 남긴 것, 신규 폼엔 복제하지 말 것)
- 13px 보조 안내(12곳)를 14px로, 링크 터치 영역 확대, 키워드 세 칸 세로 간격 축소, 선택 카드에 체크 표시 추가, 번호 원 두 어휘(섹션/키워드) 통일.
