# 부가상품 직접결제 — 블로그 고급형 신청폼

고방U사장님에서 **부가상품(블로그 고급형 150,000원, 부가세 포함)을 이미 결제한 원장님**이 키워드·요청사항을 제출하는 전용 폼.
결제가 먼저 끝난 건이라 기존 폼(15만원·10만원)과 처리 방식이 다르다. 2026-11-09 신설.

## 작성 타입 (신청 내역 M열)

| 타입 | 누가 등록 | 단가(P열, 부가세 포함) | 원장님 폼 | 키워드 | 원장님 알림톡 |
|---|---|---|---|---|---|
| `직-대기` | 알림톡 발송 때 자동 생성(11.23) | 150,000 | 아직 안 냄 | - | 키워드 폼 안내 알림톡은 이미 나감 |
| `직A`·`직B` | 원장님이 이 폼 제출 | 150,000 | ✅ | 1~3개 | 결제요청 없음 / 완료 알림톡은 기존대로 수동 |
| `직-일반` | 마케팅팀이 시트에 직접 입력 | 70,000 | 없음 | 없음 | 없음 |
| `A`·`B`·`10-A`·`10-B` | 기존 폼 | 150,000(11.16부터, 이전 165,000)·110,000 | 기존 폼 | - | 기존 그대로 |

- `직A`=설명형, `직B`=후기형. 같은 시트(`신청 내역`)에 쌓이고 작성 타입으로만 구분한다.
- `직-대기`는 "스타일(A/B)을 아직 안 골랐다"는 임시 값이다. 사장님이 폼을 내면 같은 행이 `직A`·`직B`로 바뀐다. 상태(N열)는 `응답대기`, 행 색은 회색 `#EFEFEF`.
- **지점 구분 = 신청자 칸(C열)**(11.23): 알림톡 발송 때 만든 `직-대기` 행은 신청자 칸에 일반형처럼 `지점명(번호)`가 들어가고, 사장님이 폼을 내면 그 칸이 성함으로 바뀐다. 지점명 전용 열은 만들지 않는다(기존 열 번호를 쓰는 GAS 3개·어드민·CS앱이 깨져서, 토미 11.23).
- 단가는 2026-11-09 결제화면 기준(일반 70,000 / 고급 150,000 / 빌리투어 400,000, 모두 부가세 포함). 바뀌면 `Code.gs`의 `PRICE_DIRECT_PREMIUM`, 기존 두 GAS의 `setDirectPrice_`(10만원)·`onSheetEdit`(15만원)을 같이 고친다.

## 폼 제출 시 동작 (`gas-code/Code.gs` `submitForm`)
1. 키워드 90일 선점 중복 체크(`완료 내역` 기준, 기존 폼과 같은 규칙)
2. `신청 내역`에 행 추가(11.23부터: 같은 지점번호의 가장 오래된 `직-대기` 행이 있으면 새 행 대신 그 행에 이어 씀, 결제완료일(B)은 알림 원문의 실제 결제일시를 유지하고 D-day만 제출일 기준): 결제완료일(B)=제출일 자동, 작성 타입=`직A`/`직B`, 단가 150,000, 행 노랑
3. `완료 내역`에 행 추가(발송대기) + D-day(결제완료일+7일) 갱신
4. 팀 알림메일(`설정` 시트 6행 수신자): 키워드·요청사항 포함
- **결제요청 알림톡은 보내지 않는다.** 이미 결제됐다.
- "이미 신청된 지점" 차단 없음(결제한 원장님을 돌려보내면 안 됨). 더블클릭 방지로 같은 지점 10분 내 재제출만 막는다.
- 설정 시트의 신청기간·최대 신청수·ON/OFF는 읽지 않는다. 접근 제어 없음.

## `직-일반` 운영 규칙 (마케팅팀)
- `신청 내역`에 행을 직접 추가하고 M열에 `직-일반`을 입력하면 P열 단가 70,000이 자동으로 들어간다(기존 GAS 트리거).
- **결제완료일(B열)을 반드시 같이 채운다.** 비워두면 10만원 GAS의 미결제 리마인드가 돌지만 `직*` 건은 코드에서 제외했다. 그래도 관리상 채운다.
- **`완료 내역` 행을 만들지 않는다.** 그 시트의 H열 "발송하기"는 원장님께 완료 알림톡을 보내는 스위치라, `직-일반`은 행 자체를 두지 않아야 알림톡이 나갈 수 없다.

### 결제 알림 붙여넣기 등록 (`paste.html`, 마케팅팀 전용)
- **구성(11.11 개편, 11.24 한 칸 전체 폭으로 변경)**: 데스크톱 폭(1360px), 위에서부터 결제 추이 카드 → 상품 탭(`블로그`·`빌리투어`) → 결제 알림 카드(한 줄, 결과 카드와 사용 방법이 바로 아래) → 시트 DB 카드가 한 칸 전체 폭으로 이어진다. 화면 폭과 상관없이 순서가 같다(옛 두 칸 배치는 없어졌다). 입장 때 접근 코드를 한 번 받아 서버(`checkToken`)로 확인하고 브라우저에 저장한다. 이후 등록·현황·알림톡에는 코드를 다시 묻지 않는다. 서버가 거절하면 코드를 지우고 입장 화면으로 돌아간다.
  - 바로가기는 카드 머리에 둔다: 시트 DB 카드 `시트 ↗`, 결제 알림 메시지 카드 `U사장님 ↗`. 시트 DB 표는 머리글 클릭으로 정렬(결제·지점·유형·상태, 오름/내림)하고 `상태`·`유형` 드롭다운으로 거른다.
  - **결제 알림 줄(11.24)**: 카드 머리 한 줄에 `결제 알림` ⓘ · `U사장님 ↗` · `잔디 ↗`(방 바로가기) · `설치 방법`(테두리 토글, 북마크 설치 칸) · `안 읽힌 건 붙여넣기`(테두리 토글). 잔디 읽기는 잔디 탭의 북마크가 하고(아래 "잔디 가져오기" 절), 붙여넣기 칸은 기본 접힘이다. 토글로 열면 입력 칸과 `시트에 등록하기`가 보이고, 이 붙여넣기 등록 결과는 대조 카드가 아니라 결과 카드(`#out`)에 뜬다.
  - 화면 전환 탭은 없고 상품 구분 탭(`블로그`·`빌리투어`)만 있다. 빌리투어 탭은 `부가상품 결제` 탭을 읽어 보여 주는 읽기 전용 표다(GAS `listStatus`의 `billy`). 등록하면 현황이 바로 갱신된다. 설명 문장은 화면에 두지 않고 라벨 옆 ⓘ 툴팁에 둔다.
  - `시트에 등록하기`·`알림톡 보내기`는 확인 팝업을 거친다. 작성 체크는 되돌릴 수 있어 팝업이 없다.
- **현황(시트 DB 표)**: 신청 내역 전체(부가상품 직-일반·직A·직B + 15만원·10만원 폼 건 `기존 폼`)와 최근 30일 고급형 알림톡 발송 기록을 결제 시간 최신순 한 표로 보여 준다(GAS `listStatus`, 읽기 전용). 열은 결제 | 지점 | 유형(아이콘: 일반형 문서·고급형 왕관·기존 폼 클립보드) | 상태(색 칩) | 작성. 머리말 `할 일 N건` = 작성 전 + 완료 알림 전. 카드 머리 `완료건 숨김` 체크박스가 기본 켜져 있어 작성 완료·완료 알림 보낸 건이 가려지고(머리말 `작성 완료 N건 숨김`), 끄면 흐리게 보인다(11.24). 결제 추이 카드 아래 `블로그`·`빌리투어` 탭 중 빌리투어는 아직 연결 전 안내만 있다.
  - 상태 `응답 대기`: 고급형 키워드 폼 알림톡을 보냈고 사장님 제출을 기다리는 건. 같은 지점번호(폼 지점 URL `gobang.kr/place/<번호>`)로 발송 뒤 폼이 들어오면 이 줄은 빠지고 폼 행 하나로 합쳐진다(지점명도 옮겨 온다, 11.11). 30일이 지나면 목록에서 빠진다. 휴지통 아이콘으로 지울 수 있다(GAS `hideNotified`: 숨김 표시 `PFX_` 속성만 달고 발송 기록 `PF_`는 남겨 같은 건 재발송을 계속 막는다).
  - 고급형 `작성` 체크(GAS `completePremium`): 팝업에서 장악 키워드(폼 키워드 중 선택 또는 입력)·블로그 글 주소를 넣고 `알림톡 보내기` → 완료 내역 E·F 기록 → 작업완료 알림톡(기존 시트 '발송하기'와 같은 템플릿) → G 완료일·H 발송완료·I 발송시각, 신청 내역 행 주황. 이미 보낸 건(H 발송완료 또는 I 있음)은 다시 보내지 않는다. 사장님 번호는 완료 내역 C열. 시트 DB는 10건씩 쪽을 넘긴다.
  - 상태 `작성 전` / `완료 알림 전` / `완료 알림 보냄`: 직A·직B는 `완료 내역`에서 같은 지점 URL + D-day(결제완료일+7일)가 맞는 행의 완료일·발송 값으로 정한다. 맞는 행이 없으면 그 URL의 맨 아래 행을 쓴다.
  - 일반형 `작성` 체크(GAS `markBasic`): 신청 내역 N열을 `신청완료` ↔ `작성완료`로 바꾸고 행 색을 맞춘다. 행 번호와 함께 작성 타입·신청자·결제일시를 다시 대조하고, N열이 다른 값(보류 등)이면 쓰지 않는다.
- **행 색**: 직A·직B 결제완료 = 노랑 `#FFE599`, 직-일반 결제완료 = 연파랑 `#CFE2F3`, 작성완료 = 주황 `#ff9900`(기존 관례). 10만원 GAS `onSheetEdit`도 같은 예외(`paidBg_`·`repaintPaidRow_`)를 두어, B·M·N열을 손으로 고쳐도 직-일반 색이 유지된다. 11.11 이전 직-일반 5행은 연파랑으로 소급했다.
- **결제 추이 카드(11.15 추가, 화면 맨 위 가로 띠, 아래에 상품 탭 · 결제 알림 카드 · 시트 DB가 한 칸 전체 폭으로 이어짐)**: 같은 `listStatus` 응답의 결제일시·유형·단가(`price`)로 숫자 카드 3장(누적 결제 건수·누적 매출·일/주/월평균 매출을 한꺼번에), 유형 구성 도넛 카드, 매출 막대 + 건수 꺾은선 콤보 차트 한 장(좌우 축, 범례를 눌러 계열 끄기, 칸 위에 올리면 툴팁, 일·주·월 단위), 직전 기간 대비(▲▼)를 보여 준다. **시트 DB 표에는 `단가` 열**이 있다(유형 옆, 정렬 가능, 폰 폭에서는 숨김). **매출 = 공급가액(시트 단가 ÷ 1.1)** 이고 결제액(VAT 포함)은 보조로 같이 보인다. 결제수수료·작성 정산을 뺀 실제 남는 돈(기여이익)은 원가 자료가 없어 계산하지 않는다. 계산은 `js/trend-calc.js`(순수 함수), 테스트는 `node tests/trend-calc.test.js`. 오늘은 브라우저 시간대와 무관하게 KST 기준, 결제 10건 미만이면 평균·간격을 참고용으로 알린다. 조회 조건은 `구분`·`차트`(일별·주별·월별) 드롭다운 둘과 `기간` 달력 버튼(프리셋 + 달력 그리드, 문법은 gobang-admin `DateRangePicker`). 차트 단위는 막대 칸만 바꾸고 카드 숫자는 고른 기간의 누적이다. 집계 기준은 결제일시이고 결제액은 시트 단가(부가세 포함) 합이다. 기록 시작일 이전은 그리지 않고 평균도 시작일부터만 센다(주평균은 기록 7일 이상, 월평균은 30일 이상일 때만). 고급형 응답 대기 건은 포함, 응답 대기에서 지운 건은 제외한다. 추이의 `구분` 드롭다운으로 블로그(기본, 고방 매출 기준: 일반형·고급형 + 기존 폼)·빌리투어(`부가상품 결제` 탭 금액)·전체(둘의 합)를 고른다. 기존 폼은 결제완료일이 있는 건만 센다. **시트 DB에는 신청 내역 전체(2,000행 상한)가 보인다**(11.15): 15만원·10만원 폼 건(`A`·`B`·`10-A`·`10-B`)은 유형 `기존 폼`, 상태 `결제 전`(결제완료일 없음)·`결제 완료`(있음)로 읽기 전용 표시하고 체크는 잠근다. 단가 `price`는 GAS가 P열에서 보내고, 없으면 `paste.html`의 `PRICE` 기본값(일반 70,000·고급 150,000)을 쓴다. 부품 규격은 `../docs/design-system.md` §4 `.trend`·`.kc`·`.dn`·`.plot`·`.rng`·`.c-price`.
- 고급형 알림톡 발송 기록 값(스크립트 속성 `PF_...`)은 11.11부터 `발송시각|지점명`이다(옛 건은 발송시각만 있어 현황에 `지점번호 N`으로 보인다).
- 운영팀의 "[상품 결제완료]" 메시지를 `paste.html`의 결제 알림 카드에서 `안 읽힌 건 붙여넣기`를 열어 그대로 붙여 넣으면 블로그 **일반형** 건만 `신청 내역`에 `직-일반` 행(결제완료일=결제일시, 신청자=`지점명(지점번호)`, P열 70,000)으로 등록된다. 여러 건을 한 번에 붙여 넣어도 된다.
- **고급형**은 결과 목록에 전화번호 입력 카드로 뜬다(11.09 추가). 담당자가 U사장님에서 사장님 번호를 찾아 넣고 `알림톡 발송하기`를 누르면 키워드 폼 링크 알림톡이 나간다. **알림톡을 보내면 `신청 내역`에 `직-대기` 행이 생긴다**(11.23, 결제일시·지점명·전화번호·`gobang.kr/place/<번호>`·단가 150,000). 사장님이 폼을 제출하면 같은 지점번호의 가장 오래된 대기 행이 `직A`/`직B`로 바뀐다. 대기 행이 없으면(옛 방식으로 보낸 건 등) 기존처럼 새 행이 생긴다. 현황의 `응답 대기` 휴지통은 행을 지우지 않고 상태(N열)를 `보류`로 바꾼다. 같은 지점이 보류 뒤 폼을 내면 보류 행은 쓰지 않고 새 행이 생긴다.
  - 알림톡 템플릿 ID = `Code.gs`의 `TEMPLATE_PREMIUM_FORM` 상수(스크립트 속성 `TEMPLATE_PREMIUM_FORM`이 있으면 우선, 변수 `#{지점명}` 하나, 버튼 URL은 폼 주소 고정). 없으면 발송하지 않는다.
  - 발송에는 스크립트 속성 `SOLAPI_API_KEY`·`SOLAPI_API_SECRET`·`SOLAPI_PF_ID`가 필요하다(기존 10만원·15만원 GAS와 같은 값). 점검은 편집기에서 `checkSolapiProps` 실행.

## 잔디 가져오기 (북마크 → 대조 카드 → 시트 등록, 11.24 코드·시험까지, 미배포)
잔디 방(`U사장님-콘텐츠상품`, 방 id 35912598)의 "[상품 결제완료]" 글을 사람이 붙여 넣지 않고 읽어 와서 시트와 맞춰 보고, 빠진 건만 등록한다. 읽기는 누르는 사람 본인의 잔디 탭에서 하고(토미·스티브 각자 크롬과 잔디 로그인), 판정과 등록은 GAS가 한다.

**사용 흐름**
1. 잔디에서 `U사장님-콘텐츠상품` 방을 열고 북마크 `NF 결제 가져오기`를 누른다. 화면 오른쪽 아래 패널이 방을 끝까지 읽는다(1~2분, 이 탭을 그대로 둔다).
2. 읽기가 끝나면 패널의 `결과 화면으로 보내기`를 누른다. `paste.html`이 새 창으로 열리고(이미 열려 있으면 같은 창), 후보 원문과 읽기 결과가 postMessage로 넘어간다. 보낸 곳이 잔디 도메인일 때만 받는다.
3. `paste.html`이 GAS `previewJandi`로 시트·알림톡 발송 기록과 대조해 대조 카드를 그린다(읽은 N · 이미 있음 · 새로 등록 · 전화번호가 필요한 고급형 · 빌리투어 쌓을 것 · 확인 필요 · 대상 아님, 합계가 안 맞으면 등록 버튼 잠금).
4. `시트에 등록하기`(확인 팝업)를 누르면 GAS `importJandi`가 등록한다. 일반형은 `신청 내역`에 `직-일반` 행, 빌리투어는 `부가상품 결제` 탭에 쌓는다. 고급형은 자동 등록하지 않고 전화번호 입력 카드로 간다(기존 `registerPremium` 흐름).
- 접근 코드는 `paste.html`에만 있다. 북마크는 코드를 보지도 받지도 않고, 보내는 곳은 `paste.html` 배포 주소의 출처 하나뿐이다. 잔디에서 온 글은 믿지 않는 입력이라 GAS가 원문을 다시 분류한다.
- `안 읽힌 건 붙여넣기`(기존 붙여넣기 등록 `registerPayment`)는 그대로 있고 대조 카드를 거치지 않는다(결과 카드에 뜬다). 두 길이 따로다.

**GAS 새 동작 (`gas-code/Code.gs`, 분류기 `gas-code/JandiClassify.gs`)**
| 동작 | 하는 일 |
|---|---|
| `previewJandi {token, messages[], scan}` | 읽기 전용. 글마다 분류(`blog_known`·`blog_new`·`billy`·`blog_billy`·`ignore`·`needs_review`)와 조각 판정을 돌려준다. 종결된 건에는 `closed:true`와 reason `종결됨`을 붙이고(class는 유지), 응답에 `regression.missing`(읽기 회귀 점검)을 더한다. 시트·속성에 쓰지 않는다(시험으로 고정) |
| `importJandi {token, messages[], confirm[{key,action}], scan}` | 서버가 원문을 다시 분류하고 `confirm`에 든 key만 쓴다. action = `basic`(일반형 등록)·`billy`(빌리투어 쌓기)·`close`(해당 없음으로 종결). 스크립트 잠금 안에서 실행하고 같은 호출을 되풀이해도 행이 늘지 않는다(중복 키 = 지점번호 + 결제일시 분). confirm이 비어도 확인 필요·번호 필요 조각은 로그 탭에 남긴다. 한 호출 messages 최대 500건 |
| `listStatus` | 기존 `items`·`truncated`·`build` 모양은 그대로이고 `billy:[{paidAt,branch,branchNo,product,amount,status}]`(탭 없으면 `[]`)와 `lastScan:{at,complete:true}`(없으면 `null`)가 더해졌다 |
- 읽기 회귀 점검: 로그에 있던 결제가 이번 읽은 범위 안인데 이번 글 목록에 없으면 "지난번엔 있었는데 N건이 안 보여요"로 알린다(스크롤이 덜 읽혔다는 신호).
- 마지막 수집 기록: 끝까지 읽은 스캔(`scan.complete===true`이고 중단 사유 없음)만 스크립트 속성 `JANDI_LAST_SCAN`(`{at, oldestAt, newestId}`)에 저장한다. 끝까지 못 읽었으면 갱신하지 않는다. 값은 시각·글 id뿐이라 비밀 값이 아니다.
- 새 시트 탭 2개(같은 스프레드시트, 처음 쓸 때 맨 뒤에 자동 생성, `신청 내역`의 열·행은 바뀌지 않는다):
  - `부가상품 결제`: 결제일시 / 지점명 / 지점번호 / 상품(원문 그대로, 예 `빌리투어 (투어영상)`) / 금액(그 조각 단가 400,000, 부가세 포함) / 상태(`진행전`). 블로그와 한 글에 붙은 건은 빌리투어 조각만 한 줄.
  - `잔디 수집 로그`: 수집일시 / 키(`지점번호_결제일시`) / 지점 / 판정 / 사유 / 원문(1,000자까지) / 같은 글의 동반 상품 / 메시지 결제금액 / 종결일시. 확인 필요·번호 필요의 상태 저장소다. 같은 키 + 같은 판정은 다시 쓰지 않는다.

**북마크 설치·갱신**
- 설치(토미·스티브 각자 한 번): `paste.html`의 `설치 방법`을 열고 `NF 결제 가져오기`를 북마크바로 끌어다 놓는다(크롬 북마크바는 Ctrl+Shift+B). 눌러서 쓰는 링크가 아니다.
- 만들기: `addon-direct-pay` 폴더에서 `node scripts\build-bookmarklet.js`를 돌리면 `js/jandi-reader.js`와 `js/jandi-bookmarklet-src.js`를 이어 붙여 `js/jandi-bookmarklet.txt`(`javascript:` 한 줄, 약 11KB)를 만든다. `paste.html` 설치 칸이 이 파일을 읽어 끌어다 놓을 링크로 만든다. 세 곳의 `READER_VERSION`(`js/jandi-reader.js`, `js/jandi-bookmarklet-src.js`, 화면 쪽 `js/jandi-bridge.js`의 `EXPECTED_VERSION`)이 다르면 빌드가 실패한다.
- 갱신: 읽기 코드(`jandi-reader.js`·`jandi-bookmarklet-src.js`)가 바뀌면 `READER_VERSION`을 세 곳 모두 올리고 빌드한 뒤, `js/jandi-bookmarklet.txt`·`paste.html`·`js/`를 올리고 2대에서 북마크를 다시 끌어다 놓는다. 옛 북마크로 보내면 화면이 "북마크가 오래됐어요" 안내를 띄운다. 이 README의 아래 버전 줄과 `paste.html` 설치 칸의 `북마크 버전 N` 문구도 같이 고친다. `GAS 배포 (딸깍).bat`의 값은 GAS `BUILD` 전용이라 `READER_VERSION`과 무관하다(GAS 코드를 고칠 때만 `BUILD`와 함께 바꾼다).
- 현재 `READER_VERSION` = 1.

**아직 안 된 것 (미배포·미확인)**
1. 실제 GAS에서 한 번도 돌리지 않았다(시트·속성 목 시험만). `insertSheet`로 만든 탭 위치, 잠금, 날짜 서식은 배포 뒤 확인한다.
2. 실제 잔디 화면에서 북마크 실행, `window.open`, postMessage 연결, 브라우저의 창 간 격리 정책(COOP)이 `paste.html` 새 창과의 연결을 막는지는 확인하지 못했다. 읽기 자체는 11.24에 실제 방에서 시험했다.
3. 약 11KB의 `javascript:` 북마크가 크롬 북마크 동기화와 북마크바에서 그대로 유지되는지 미확인이다.
4. 잔디 방 주소(`js/jandi-ui.js`의 `JANDI_ROOM_URL` = `https://neoflat.jandi.com/app/#!/room/35912598`)는 11.24 실측한 주소를 가정한 값이다.
5. 잔디 약관(자동 화면 읽기 조항)은 확인하지 못했다.
6. 저장소 밖 시트 바인딩 스크립트·시트 안 수식이 새 탭 2개를 건드리는지 미확인이다.
7. 붙여넣기 등록은 대조 카드를 거치지 않는다. 안 읽힌 건을 붙여 넣을 때는 대조가 없다.
8. `paste.html` 접근 보호는 접근 코드 한 가지뿐이다(코드를 아는 사람은 누구든 등록할 수 있고, 등록한 사람은 기록되지 않는다).

**운영 규칙**: 결제 알림은 원문 그대로 올린다. 사람이 문구·줄바꿈·숫자를 고쳐 올린 글은 정확한 규칙을 통과하지 못해 `확인 필요`로 밀리고 일부 항목은 못 읽을 수 있다. 말을 덧붙일 때는 원문을 고치지 말고 별도 글로 올린다.
