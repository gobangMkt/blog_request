# 부가상품 직접결제 — 블로그 고급형 신청폼

고방U사장님에서 **부가상품(블로그 고급형 150,000원, 부가세 포함)을 이미 결제한 원장님**이 키워드·요청사항을 제출하는 전용 폼.
결제가 먼저 끝난 건이라 기존 폼(15만원·10만원)과 처리 방식이 다르다. 2026-11-09 신설.

## 작성 타입 (신청 내역 M열)

| 타입 | 누가 등록 | 단가(P열, 부가세 포함) | 원장님 폼 | 키워드 | 원장님 알림톡 |
|---|---|---|---|---|---|
| `직A`·`직B` | 원장님이 이 폼 제출 | 150,000 | ✅ | 1~3개 | 결제요청 없음 / 완료 알림톡은 기존대로 수동 |
| `직-일반` | 마케팅팀이 시트에 직접 입력 | 70,000 | 없음 | 없음 | 없음 |
| `A`·`B`·`10-A`·`10-B` | 기존 폼 | 165,000·110,000 | 기존 폼 | - | 기존 그대로 |

- `직A`=설명형, `직B`=후기형. 같은 시트(`신청 내역`)에 쌓이고 작성 타입으로만 구분한다.
- 단가는 2026-11-09 결제화면 기준(일반 70,000 / 고급 150,000 / 빌리투어 400,000, 모두 부가세 포함). 바뀌면 `Code.gs`의 `PRICE_DIRECT_PREMIUM`, 기존 두 GAS의 `setDirectPrice_`(10만원)·`onSheetEdit`(15만원)을 같이 고친다.

## 폼 제출 시 동작 (`gas-code/Code.gs` `submitForm`)
1. 키워드 90일 선점 중복 체크(`완료 내역` 기준, 기존 폼과 같은 규칙)
2. `신청 내역`에 행 추가: 결제완료일(B)=제출일 자동, 작성 타입=`직A`/`직B`, 단가 150,000, 행 노랑
3. `완료 내역`에 행 추가(발송대기) + D-day(결제완료일+7일) 갱신
4. 팀 알림메일(`설정` 시트 6행 수신자): 키워드·요청사항 포함
- **결제요청 알림톡은 보내지 않는다.** 이미 결제됐다.
- "이미 신청된 지점" 차단 없음(결제한 원장님을 돌려보내면 안 됨). 더블클릭 방지로 같은 지점 10분 내 재제출만 막는다.
- 설정 시트의 신청기간·최대 신청수·ON/OFF는 읽지 않는다. 접근 제어 없음.

## `직-일반` 운영 규칙 (마케팅팀)
- `신청 내역`에 행을 직접 추가하고 M열에 `직-일반`을 입력하면 P열 단가 70,000이 자동으로 들어간다(기존 GAS 트리거).
- **결제완료일(B열)을 반드시 같이 채운다.** 비워두면 10만원 GAS의 미결제 리마인드가 돌지만 `직*` 건은 코드에서 제외했다. 그래도 관리상 채운다.
- **`완료 내역` 행을 만들지 않는다.** 그 시트의 H열 "발송하기"는 원장님께 완료 알림톡을 보내는 스위치라, `직-일반`은 행 자체를 두지 않아야 알림톡이 나갈 수 없다.

### 결제 알림 붙여넣기 등록 (`paste.html`, 마케팅팀 전용)
- **구성(11.11 개편)**: 데스크톱 폭(1360px), 한 판 두 칸(왼쪽 등록 · 오른쪽 현황 표가 더 넓음, 1100px 이하는 위아래). 입장 때 접근 코드를 한 번 받아 서버(`checkToken`)로 확인하고 브라우저에 저장한다. 이후 등록·현황·알림톡에는 코드를 다시 묻지 않는다. 서버가 거절하면 코드를 지우고 입장 화면으로 돌아간다.
  - 헤더 오른쪽 `시트 ↗`(신청 내역) · `U사장님 ↗`.
  - 탭 없음. 등록하면 현황이 바로 갱신된다. 설명 문장은 화면에 두지 않고 라벨 옆 ⓘ 툴팁에 둔다.
  - `시트에 등록하기`·`알림톡 보내기`는 확인 팝업을 거친다. 작성 체크는 되돌릴 수 있어 팝업이 없다.
- **현황(왼쪽 표)**: 신청 내역 최근 500행의 부가상품 건(직-일반·직A·직B)과 최근 30일 고급형 알림톡 발송 기록을 결제 시간 최신순 한 표로 보여 준다(GAS `listStatus`, 읽기 전용). 열은 결제 | 지점 | 유형(아이콘: 일반형 문서·고급형 왕관) | 상태(색 칩) | 작성. 머리말 `할 일 N건` = 작성 전 + 완료 알림 전.
  - 상태 `폼 안내함`: 고급형 키워드 폼 알림톡을 보낸 기록이다. 폼은 지점번호를 받지 않아 어느 제출이 이 건인지 알 수 없으므로 짝짓지 않는다.
  - 상태 `작성 전` / `완료 알림 전` / `완료 알림 보냄`: 직A·직B는 `완료 내역`에서 같은 지점 URL + D-day(결제완료일+7일)가 맞는 행의 완료일·발송 값으로 정한다. 맞는 행이 없으면 그 URL의 맨 아래 행을 쓴다.
  - 일반형 `작성` 체크(GAS `markBasic`): 신청 내역 N열을 `신청완료` ↔ `작성완료`로 바꾸고 행 색을 맞춘다. 행 번호와 함께 작성 타입·신청자·결제일시를 다시 대조하고, N열이 다른 값(보류 등)이면 쓰지 않는다.
- **행 색**: 직A·직B 결제완료 = 노랑 `#FFE599`, 직-일반 결제완료 = 연파랑 `#CFE2F3`, 작성완료 = 주황 `#ff9900`(기존 관례). 10만원 GAS `onSheetEdit`도 같은 예외(`paidBg_`·`repaintPaidRow_`)를 두어, B·M·N열을 손으로 고쳐도 직-일반 색이 유지된다. 11.11 이전 직-일반 5행은 연파랑으로 소급했다.
- 고급형 알림톡 발송 기록 값(스크립트 속성 `PF_...`)은 11.11부터 `발송시각|지점명`이다(옛 건은 발송시각만 있어 현황에 `지점번호 N`으로 보인다).
- 운영팀의 "[상품 결제완료]" 메시지를 `paste.html`에 그대로 붙여 넣으면 블로그 **일반형** 건만 `신청 내역`에 `직-일반` 행(결제완료일=결제일시, 신청자=`지점명(지점번호)`, P열 70,000)으로 등록된다. 여러 건을 한 번에 붙여 넣어도 된다.
- **고급형**은 결과 목록에 전화번호 입력 카드로 뜬다(11.09 추가). 담당자가 U사장님에서 사장님 번호를 찾아 넣고 `알림톡 발송하기`를 누르면 키워드 폼 링크 알림톡이 나간다. **시트에는 쓰지 않는다.** 사장님이 폼을 제출하면 기존처럼 `직A`/`직B` 행이 새로 생긴다(폼은 지점번호를 받지 않는다).
  - 알림톡 템플릿 ID = `Code.gs`의 `TEMPLATE_PREMIUM_FORM` 상수(스크립트 속성 `TEMPLATE_PREMIUM_FORM`이 있으면 우선, 변수 `#{지점명}` 하나, 버튼 URL은 폼 주소 고정). 없으면 발송하지 않는다.
  - 발송에는 스크립트 속성 `SOLAPI_API_KEY`·`SOLAPI_API_SECRET`·`SOLAPI_PF_ID`가 필요하다(기존 10만원·15만원 GAS와 같은 값). 점검은 편집기에서 `checkSolapiProps` 실행.
  - 같은 건(지점번호+결제일시)은 발송 기록(`PF_...` 속성)이 있으면 두 번 보내지 않는다. 실패하면 같은 번호로 다시 누르면 된다.
  - 카드의 `U사장님에서 지점 찾기` 링크는 `paste.html`의 `USABOSS_URL`(현재 https://u-ceo.kr, 비우면 숨김).
- 블로그 상품이 없는 건은 건너뛴다. 같은 지점·결제일시는 중복 등록하지 않는다. `완료 내역` 행과 팀 알림메일은 만들지 않는다.
- 접근 코드 = 이 GAS 스크립트 속성 `INBOX_TOKEN` 값. 한 번 입력하면 브라우저에 저장된다. 코드가 틀리면 등록되지 않는다.
- 잔디 채팅방에는 웹훅(커넥트) 메뉴가 없어서 자동 수신 대신 붙여 넣기 방식으로 만들었다(11.09 결정).

## 접근
- **링크 발급·서명 없이 공개 신청 페이지 하나다.** 마케팅팀이 결제를 확인한 원장님께 이 주소를 보낸다.
- 제출은 결제완료로 기록되고 팀 알림메일이 나가므로, 알림메일을 받은 마케팅팀이 U사장님 결제 건과 대조해 가짜 제출을 거른다.
- 검색에 노출되지 않게 `noindex`를 걸어 두었다.
